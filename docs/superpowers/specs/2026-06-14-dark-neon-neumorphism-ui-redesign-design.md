# 暗黑霓虹新拟物全站 UI 重构设计

## 背景

前端是 Vue 3 + Vite + TailwindCSS 应用，页面覆盖公开页、认证页、用户端、销售端、管理后台、支付流程、回调页和 404。当前 UI 以浅色/蓝色后台风格为主，暗色模式已有基础支持，但视觉语言不符合新的设计目标。

本次目标是一次覆盖所有前端页面，重构为强视觉冲击、赛博感明显的暗黑霓虹新拟物风。功能完整性以 `docs/frontend-ui-function-inventory.md` 为逐页验收矩阵。

已有无关工作区改动包括 `.dockerignore`、`Dockerfile`、`deploy/.gitignore` 和 `.superpowers/`，本设计不要求修改或回退这些内容。

## 已确认决策

- 改造范围选择方案 C：所有前端页面逐页重构。
- 只保留暗黑主题；明暗主题切换入口从 UI 中移除或隐藏。
- 视觉基线选择强赛博方向：高饱和霓虹、明显暗黑新拟物光影、多栏模块卡片、状态环和内凹控件。
- 不改变业务能力、路由结构、权限控制、API 契约和支付/认证流程。

## 设计原则

1. 功能优先保全。每个页面改造前后都需要对照功能盘点表，保留原有字段、按钮、筛选、分页、批量操作、弹窗、导入导出、回调状态和错误处理。
2. 暗黑单主题一致。全站不再为浅色主题优化，基础背景、文字、边框、控件、图表容器和弹窗都以暗色可读性为准。
3. 赛博感强，但数据可读。霓虹可以明显，但表格、长表单、设置页和日志页不能牺牲扫描效率。
4. 使用共享设计系统。先建立全局 token、基础类和壳层，再逐页精修，避免 60 多个视图产生互相冲突的局部样式。
5. 不做无关重构。除 UI 结构和必要组件抽象外，不调整后端、接口、状态管理语义或业务规则。

## 视觉系统

### 基底

全站使用炭黑和深灰暗色底：

- 页面背景：接近黑色的炭黑渐变，用低亮度层次区分主区域和导航区域。
- 内容表面：深灰半透明磨砂玻璃，带轻微噪声质感或细微高光。
- 分隔线：低对比度冷灰和半透明霓虹边线。

### 强调色

建立高饱和霓虹马卡龙数据色：

- 青蓝：主操作、冷区、同步、API、通用信息。
- 玫粉：高热度、风险、费用、强提醒。
- 荧光绿：成功、健康、可用、通过。
- 暖橙：等待、警告、支付、临界值。
- 紫色：系统、配置、分组、智能/模型相关数据。

颜色必须服务信息识别，不把所有元素都染成同一色系。

### 新拟物光影

- 卡片：轻微上浮，外部柔光和反向冷光，边缘有半透明描边。
- 输入、筛选、滑块、开关、分页器：内凹阴影，体现可操作控制面。
- 按钮：主按钮使用霓虹渐变和柔光；危险/成功/警告按钮分别使用对应数据色。
- 弹窗和抽屉：暗色玻璃表面，强层级遮罩，保持表单可读。
- 圆角：整体更柔和，但表格和密集后台区域要控制圆角，不让信息密度下降。

### 状态环

新增统一状态环语言，用于余额、额度、可用率、使用率、响应时间、风险等级和订阅进度：

- 冷区：蓝/青渐变。
- 暖区：粉/橙渐变。
- 健康区：绿/青渐变。
- 风险区：粉/橙/红增强。

状态环仅用于摘要和关键状态，不替代表格中的精确数值。

## 页面架构

### 全局壳层

`AppLayout`、`AppHeader`、`AppSidebar` 是全站视觉基础：

- 侧栏改为暗黑玻璃新拟物面板，保留折叠、移动端抽屉、角色菜单、功能开关隐藏逻辑和账号菜单。
- 头部改为紧凑霓虹玻璃工具栏，保留页面标题、描述、公告、文档、语言、余额、订阅进度和账号相关入口。
- 主内容区改为深色网格背景和模块化内容区，移动端保持安全间距。
- 主题切换按钮移除或隐藏；暗黑主题成为唯一呈现。

### 公开和认证页面

包括 `/home`、`/login`、`/register`、邮箱验证、OAuth 回调、密码找回、免登录查询和法务文档：

- 登录/注册使用居中流程卡，背景为强霓虹暗黑空间。
- 表单字段保留 Turnstile、邀请码、优惠码、协议、TOTP、OAuth 入口和密码显隐。
- 回调页保留状态机反馈，使用霓虹进度、成功、失败和补充资料面板。
- 法务和自定义内容保持阅读优先，霓虹只做边框和导航强调。

### 用户端页面

包括仪表盘、API Keys、Playground、用量、兑换、推广、模型广场、渠道状态、个人资料、订阅、购买、订单、支付页和自定义页：

- 仪表盘采用多栏栅格：数据卡、趋势图、最近请求和快捷动作模块化。
- API Keys 页面使用筛选控制台、密钥卡/表格、编辑弹窗和危险操作确认。
- 用量和渠道状态页面加强图表容器、状态环和错误详情层级。
- 支付流程突出当前步骤、金额、支付方式、手续费和轮询状态，保留二维码、Stripe、Airwallex 和微信恢复逻辑。
- Profile 和设置类页面按分区模块组织，降低长表单压迫感。

### 销售端页面

销售仪表盘、客户、订单和推广页保持后台效率：

- 统计卡使用不同数据色区分客户、订单、成交金额和推广。
- 客户/订单列表保留搜索、筛选、分页和跳转关系。
- 推广链接操作保留复制、打开注册页、禁用和吊销。

### 管理后台页面

管理后台是重构重点，覆盖仪表盘、运维监控、用户、分组、渠道、订阅、账号、公告、代理、兑换码、优惠码、系统设置、风控、用量、推广和支付管理：

- 大型表格页统一为“筛选控制台 + 数据表/卡片 + 批量操作条 + 详情弹窗/抽屉”。
- 运维监控使用强赛博监控台布局，全屏、图表、告警、日志、详情弹窗都保留。
- 系统设置使用模块化 tab 和分区卡，避免一屏过多边框竞争。
- 账号管理、用户管理、分组管理等复杂页保留列设置、自动刷新、导入导出、批量编辑、测试、重授权、隐私模式等高风险功能。
- 风控和错误详情页强化风险色，但保留日志可读性。

### 404 和重定向页

404 保留返回上一页和返回首页。重定向页不做视觉负担，只保证加载状态符合暗黑主题。

## 组件和样式策略

### 全局 token

更新 `frontend/tailwind.config.js`：

- 增加 charcoal/dark surface 色阶。
- 增加 neon cyan、pink、lime、orange、purple 色阶。
- 增加 neumorphic shadow、inner shadow、neon glow、glass border 和 status ring gradient。
- 保留现有 Tailwind 使用方式，减少页面迁移成本。

### 全局类

更新 `frontend/src/style.css` 中共享类：

- `.card`、`.glass`、`.glass-card`、`.card-glass`
- `.btn`、`.btn-primary`、`.btn-secondary`、`.btn-danger`、`.btn-success`、`.btn-warning`
- `.input`、`.input-label`、`.input-hint`、`.input-error`
- `.table`、`.table-container`、`.table-wrapper`
- `.badge` 及各状态色
- `.dropdown`、`.dropdown-item`
- `.modal-*`、`.dialog-*`
- `.tabs`、`.tab`、`.progress`、`.switch`
- `.sidebar-*`、`.page-*`、`.empty-state`、`.skeleton`

### 页面级重构

逐页清理浅色残留和单一蓝色残留：

- 将硬编码 `bg-white`、`bg-gray-*`、`text-gray-*`、`border-gray-*` 等替换为暗黑霓虹体系。
- 对复杂页面引入页面级布局容器，但不改变数据来源和事件处理。
- 对重复结构抽取小组件时，必须保持 props/events 清晰，不做业务改名。
- 图表容器统一深色背景、低对比网格线和霓虹数据色。

## 功能保全矩阵

功能保全以 `docs/frontend-ui-function-inventory.md` 为主表。实施时每个页面至少核对：

- 路由是否仍可访问，权限守卫是否保持。
- 页面所有表单字段、默认值、校验、错误提示是否保留。
- 搜索、筛选、排序、分页、刷新、自动刷新是否保留。
- 批量操作、导入、导出、复制、打开外链、下载是否保留。
- 弹窗、抽屉、确认框、详情面板、二维码、轮询状态是否保留。
- 移动端菜单、表格横向滚动、移动卡片布局是否可用。
- 功能开关隐藏菜单和简单模式逻辑是否保留。
- 支付、OAuth、TOTP、邮箱验证、回调页状态是否不被视觉重构破坏。

## 验证计划

基础验证命令：

```bash
pnpm --dir frontend typecheck
pnpm --dir frontend test:run
pnpm --dir frontend build
```

视觉和交互验证：

- 启动前端本地服务，检查桌面和移动端关键页面。
- 桌面重点看 `/dashboard`、`/keys`、`/usage`、`/purchase`、`/admin/dashboard`、`/admin/ops`、`/admin/users`、`/admin/accounts`、`/admin/settings`、`/admin/usage`。
- 公开/认证重点看 `/home`、`/login`、`/register`、`/key-usage`、`/payment/qrcode`、`/payment/result`。
- 检查文字不重叠、按钮文字不溢出、弹窗不超出视口、表格可横向滚动、深色背景下所有状态色可读。
- 检查只保留暗黑主题后，没有浅色主题残留入口。

## 非目标

- 不改后端接口和数据结构。
- 不重写路由守卫、认证状态管理或支付业务流程。
- 不删除已有业务功能。
- 不追求所有页面完全相同布局；不同页面可以按仪表盘、表格、设置、支付、认证等类型采用不同模块模板。
- 不为浅色主题做视觉适配。

## 完成标准

重构完成后，全站前端页面均为暗黑霓虹新拟物风格，且视觉基线与已确认方向一致。所有页面功能对照盘点表无遗漏，核心验证命令通过，关键桌面和移动端页面人工检查无明显布局错位、文字遮挡、弹窗溢出或不可读控件。
